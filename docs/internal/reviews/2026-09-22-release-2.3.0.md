# Windows-Release 2.3.0

Die Version ergänzt die zentrale Datenprüfung sowie Jahres-VZÄ per Monatsenddurchschnitt. Die taggewichtete Alternative wird zusammen mit dem Standard unter Einstellungen → Allgemein gewählt. Dashboard, Jahrestabelle und Exporte verwenden dieselbe Einstellung. Die Berechnungsart steht als Hover-Hinweis an den Werten. Der fachliche Vertragsmatrix-Abgleich ist nicht enthalten.

PR #54 wurde unabhängig auf Commit `9063e14789d6bbc36b200825da22349a748cfaa6` geprüft und als `63d8f64a463018abfa795725fba977e27f0d96c2` gemergt. Das Review fand keine Blocker; 52 gezielte Tests bestanden erneut. Auch die Änderungen an den Release-Prüfungen wurden unabhängig geprüft.

Der Release-Kandidat ist `4f8596bbc73db9128c4a9bc29a55cd4feeb3fa45` aus PR #55. Für synchronisierte Datenbestände muss der Server die aktuelle `src/shared/syncSchema.json` verwenden, damit er den neuen Schlüssel `annualFteMethod` akzeptiert. Dieser Desktop-Release führt kein Serverdeployment aus.

Die nativen Prüfungen verwenden synthetische verschlüsselte Profile und kontrollieren Passwort, Schlüssel, Datensätze, Einstellungen und Benutzerpräferenzen über zwei Neustarts. Von 2.1.0 wird eine Migrationssicherung erwartet; ab 2.2.0 bleibt Schema 23 erhalten. Die 2.1.0-Basis wird aus dem bereinigten Tag neu gebaut, weil der ursprüngliche Installer nicht mehr verfügbar ist. Die Originalinstaller 2.2.0 und 2.2.1 werden vor Verwendung gegen archivierte SHA-256-Werte geprüft.

Die neue Einstellung wird auch im installierten Programm geprüft. Der Testnachfolger 2.3.1 übernimmt dabei die zuvor gespeicherte taggewichtete Methode. Er wird nicht veröffentlicht. Screenshots stammen aus dem installierten Windows-Programm mit echter Navigation.

Der erste Kandidatenlauf 35761846504 erreichte auf allen vier Wegen das installierte Zielprogramm, scheiterte anschließend aber am unbeschrifteten Sperr-Symbol in der schmalen Einstellungsleiste. Die Symbolbuttons haben nun zugängliche Namen. Auch diese Korrektur wurde unabhängig geprüft. Der vollständige Kandidatenlauf wurde danach neu gestartet; keine Prüfung wurde entfernt oder abgeschwächt.
